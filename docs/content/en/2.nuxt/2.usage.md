ODX provides a reactive, type-safe wrapper around Nuxt's `useFetch` called `useOData`.

## Usage Patterns

:::tabs{.w-full}
  :::tabs-item{label="Dot-Notation" icon="i-lucide-mouse-pointer-2"}
  The recommended way to access your OData services. It provides full IDE autocomplete for service and entity names.

  ```vue [app.vue]
  <script setup lang="ts">
  const { data } = await useOData().V2Service.Products.list({
    $select: ['ProductID', 'ProductName'],
    $filter: 'UnitPrice gt 20'
  })
  </script>
  ```
  :::

  :::tabs-item{label="Functional" icon="i-lucide-code"}
  Use this for dynamic service or entity names (e.g., from route parameters).

  ```ts
  const service = 'V2Service'
  const entity = 'Products'
  const { data } = await useOData(service).entitySet(entity).list()
  ```
  :::
:::

## Available Methods

Every entity set provides the following CRUD methods:

:::field-group
  :::field{name=".list(query?, options?)" type="GET"}
  Fetches a collection of entities.
  :::

  :::field{name=".get(id, query?, options?)" type="GET"}
  Fetches a single entity by its primary key.
  :::

  :::field{name=".create(payload)" type="POST"}
  Creates a new entity.
  :::

  :::field{name=".update(id, payload)" type="PATCH"}
  Updates an existing entity.
  :::

  :::field{name=".remove(id)" type="DELETE"}
  Removes an entity.
  :::
:::

## Nitro Server Reads

Use the request-scoped read service inside Nitro endpoints. It resolves a
configured logical service, retains the current H3 request context, and keeps
proxy routes and OData path construction out of application code.

```ts [server/api/products.get.ts]
import { createODataServerReadService } from '@me-tools/odx-nuxt/server'

export default defineEventHandler((event) => {
  const catalog = createODataServerReadService(event, 'catalog')
  return catalog.entitySet('Products').fetchPage({
    $select: ['ID', 'Name'],
    $top: 30,
    $count: true,
  })
})
```

The entity-set service exposes:

:::field-group
  :::field{name=".fetchOne(key, query?, options?)" type="GET"}
  Reads one entity by a validated scalar, composite, or structured key.
  :::

  :::field{name=".fetchOneWithResponse(key, query?, options?)" type="GET"}
  Reads the same exact entity while preserving its optional ETag for a conditional follow-up mutation.
  :::

  :::field{name=".fetchContainedOneWithResponse(source, query?, options?)" type="GET"}
  Reads an exact contained entity from a structured root key and containment path while preserving its optional ETag.
  :::

  :::field{name=".fetchNavigationOneWithResponse(request, options?)" type="GET"}
  Reads a single-valued navigation or one keyed member of a related collection while preserving its optional ETag.
  :::

  :::field{name=".fetchList(query?, options?)" type="GET"}
  Reads and flattens a collection.
  :::

  :::field{name=".fetchPage(query?, options?)" type="GET"}
  Reads a collection while preserving its count and opaque continuation.
  :::

  :::field{name=".fetchNextPage(continuation, options?)" type="GET"}
  Continues the same collection by anchoring its opaque token to the validated request-scoped proxy path.
  :::

  :::field{name=".fetchNavigationList(source, path, query?, options?)" type="GET"}
  Reads a related collection below a structured root identity.
  :::

  :::field{name=".fetchNavigationPage(source, path, query?, options?)" type="GET"}
  Reads the same related collection with count and continuation metadata.
  :::

  :::field{name=".fetchNavigationNextPage(source, path, continuation, options?)" type="GET"}
  Continues that exact related collection without following a backend-owned URL.
  :::

  :::field{name=".invokeFunction(name, invocation?, options?)" type="GET"}
  Invokes a qualified OData V4 function with typed primitive parameters and an optional entity or navigation binding.
  :::
:::

## Nitro Server Mutations

Use the request-scoped server mutation service when a Nitro endpoint executes a
validated application command. It resolves the named service from the current
ODX module configuration, calls the application-origin proxy route with the
current H3 request context, and keeps executable OData URLs and multipart batch
serialization out of application code.

```ts [server/api/archive-product.post.ts]
import { createODataServerMutationService } from '@me-tools/odx-nuxt/server'

export default defineEventHandler(async (event) => {
  const catalog = createODataServerMutationService(event, 'catalog')
  const products = catalog.entitySet('Products')

  return products.invokeWithResponse(
    'Catalog.ArchiveProduct',
    { key: 42, parameters: { Reason: 'obsolete' } },
    { headers: { 'If-Match': 'W/"product-7"' } },
  )
})
```

The entity-set service exposes:

:::field-group
  :::field{name=".create(body, options?)" type="POST"}
  Creates an entity in the configured entity set.
  :::

  :::field{name=".createWithResponse(body, options?)" type="POST"}
  Creates an entity while retaining its optional representation, ETag, entity ID, location, and SAP message.
  :::

  :::field{name=".update(key, body, options?)" type="PATCH"}
  Updates the exact scalar, composite, or structured entity identity.
  :::

  :::field{name=".updateWithResponse(key, body, options?)" type="PATCH"}
  Updates the same entity while retaining its optional representation, next ETag, and SAP message.
  :::

  :::field{name=".remove(key, options?)" type="DELETE"}
  Deletes the exact scalar, composite, or structured entity identity.
  :::

  :::field{name=".removeWithResponse(key, options?)" type="DELETE"}
  Deletes the same entity while retaining its optional representation, next ETag, and SAP message.
  :::

  :::field{name=".fetchMedia(key, options?)" type="GET"}
  Reads a default or named binary stream imperatively with content type, disposition, and ETag metadata.
  :::

  :::field{name=".updateMedia(key, body, options)" type="PUT"}
  Replaces a default or named binary stream with an exact content type and optional concurrency validator.
  :::

  :::field{name=".invoke(action, invocation?, options?)" type="POST"}
  Invokes a qualified action with an optional structured key and parameters.
  :::

  :::field{name=".invokeWithResponse(action, invocation?, options?)" type="POST"}
  Invokes the same qualified action while retaining its optional representation, next ETag, response location, and SAP message.
  :::

  :::field{name=".linkNavigation(source, path, targetSet, targetKey, options?)" type="POST"}
  Creates an entity reference without creating the target entity.
  :::

  :::field{name=".linkNavigationWithResponse(source, path, targetSet, targetKey, options?)" type="POST"}
  Links the same existing entity while retaining the optional representation, next ETag, and SAP message.
  :::

  :::field{name=".unlinkNavigation(source, path, targetKey, options?)" type="DELETE"}
  Removes only the addressed relationship.
  :::

  :::field{name=".unlinkNavigationWithResponse(source, path, targetKey, options?)" type="DELETE"}
  Removes the same relationship while retaining the optional representation, next ETag, and SAP message.
  :::
:::

Use `service.changeSet(mutations, options?)` when a validated command group must
succeed or fail atomically. ODX validates every structured mutation, builds the
service-relative member paths, serializes one multipart changeset, and parses
the ordered member responses.

These server APIs do not replace application-level validation. Resolve entity
sets, actions, keys, parameters, authorization, and ETags from trusted metadata
and host policy before execution. Do not accept a service name, action, or
arbitrary upstream URL directly from untrusted request input.

The proxy continues to own configured authentication, destination resolution,
SAP CSRF, session cookies, policy checks, error sanitization, and telemetry.
Forward the entity's current ETag through `If-Match`; do not retry a `409` or
`412` with a wildcard validator.

## Query Parameters

The `.list()` and `.get()` methods accept an `ODataQuery` object:

:::field-group
  :::field{name="$select" type="string | string[]"}
  Fields to include in the response.
  :::

  :::field{name="$filter" type="string"}
  OData filter expression (e.g. `Price gt 10`).
  :::

  :::field{name="$orderby" type="string"}
  Sort order (e.g. `Price desc, Name asc`).
  :::

  :::field{name="$top" type="number"}
  Limit the number of results to return.
  :::

  :::field{name="$skip" type="number"}
  Number of results to skip for pagination.
  :::

  :::field{name="$expand" type="string"}
  Navigation properties to include in the response.
  :::
:::
